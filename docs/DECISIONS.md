Each entry: ID · decision · why. Newest at the bottom.

| --- | --- | --- |
| **D-001** | Product brand is **MEMBRANE.AI** (single name). | "Dev-AI" was a working alias; dropped everywhere. |
| **D-002** | All repo content (code, docs, README) in **English**; **replies to the user always in Turkish**. | Universal codebase + the user's preferred conversation language. |
| **D-003** | Repo lives at **`C:\Dev\Membrane-AI`**, outside OneDrive. | Avoids OneDrive sync locking `.git`/`node_modules`/build artifacts. |
| **D-004** | **Microservice** architecture, each service **hexagonal** (ports & adapters). | Independent deploy/scale; testable domain; the "ultra-premium" bar. |
| **D-005** | **Go** for core/edge/data services; **Python (FastAPI)** only for the semantic-AI service. | Go = static binaries, concurrency, low footprint; Python = ML ecosystem. |

| **D-007** | State: **Redis** (Blake3 verdict cache, 72h volatile-lru) + **Aurora PostgreSQL + pgvector/HNSW** (rules, gold-codebase index, audit). | Sub-ms skips + durable relational + vector search in one store. |
| **D-008** | Cost control: **three-tier gating** — cache → context pruning → local model triage → premium consensus only on risk. | Makes per-push LLM review economically viable. |
| **D-009** | Models: cloud consensus = **Claude Sonnet 4.6** (+ Gemini); local = **DeepSeek-Coder/CodeLlama** on vLLM; embeddings = OpenAI `text-embedding-3-large`. | Current models (replaced stale Claude 3.5 / Gemini 1.5 refs). |
| **D-010** | **Cross-platform**: static Go client binaries (`CGO_ENABLED=0`, win/mac/linux × amd64/arm64, glibc+musl) + multi-arch distroless service containers; runs on any Linux distro & any Kubernetes. | Run everywhere developers/pipelines run; clears regulated-industry bar. |
| **D-011** | **Deployment postures**: Masked SaaS · Private VPC · Air-gapped on-prem. | Match isolation to customer; air-gapped unblocks banks/defense. |
| **D-012** | **Push only on "pushla"**; commit identity fixed to Özgür Işık Damar; **no AI trailers**; commits short/English. | User's standing workflow rules. |
| **D-013** | DB↔Kafka consistency via **transactional outbox** (ACID write + relay), not dual-write. | Exactly-once-ish event emission without distributed transactions. |
| **D-014** | Doc build pipeline (report/blueprint docx) = matplotlib figures + `marked`+`docx-js`; visual QA via Word COM → PDF → PyMuPDF. Masters live in `docs/report` & `docs/blueprint`. | Reproducible; graphviz/mermaid/LibreOffice not installed. |
| **D-015** | Monorepo with **`go.work`**; each service is its own Go module; shared code in **`pkg/`**; protobuf via **buf**; task runner **go-task** (`Taskfile.yml`). | Clean module boundaries + one-command DX. |
| **D-016** | Project tracking: **`docs/ROADMAP.md` is the source of truth**; GitHub Project #5 board is a mirror. | Docs work offline and across any model/session. |
| **D-017** | First service built in P0 = **`ingestion`** (gRPC stream + Git webhook → Kafka). | It is the entry point of the whole pipeline; everything else consumes its events. |
| **D-018** | **Analyzer is a separate gRPC microservice** (`membrane.analyzer.v1`); the orchestrator calls it as a remote `AnalysisStage` (config `MEMBRANE_ORCHESTRATOR_ANALYZER_ADDR`; empty ⇒ in-process secret-scan only). The in-process secret scan always remains the deterministic fallback. | Matches the microservice architecture (D-004) and the report's analyzer pods; lets the analyzer scale/deploy independently; Saga already degrades safely on stage errors. |
| **D-019** | Analyzer v1 detectors are **line-scan based** (secrets + masking + risky patterns). **AST detectors are deferred** until the context resolver provides full-file content (a diff alone cannot be parsed into a meaningful AST). | Honest scope: no fake AST; masking is the privacy-critical deliverable (secrets never reach LLM stages). |
| **D-020** | Resolver ships with a **deterministic stub embedder** (signed feature-hashing of token shingles, L2-normalized) behind the `ports.Embedder` swap point until the semantic service provides real embeddings. **3072-dim embeddings are HNSW-indexed via a `halfvec` expression index** (pgvector caps plain `vector` HNSW at 2000 dims); queries MUST use the same `embedding::halfvec(3072)` expression to hit the index. Org IDs are strict UUIDs at the resolver boundary (schema is UUID-keyed). | Unblocks the full RAG plumbing now (proven by a live integration test); real embeddings drop in by replacing one adapter. |
| **D-021** | **Outbox relay runs in-process** inside the orchestrator (interval poller, default 500ms/100 rows) using `FOR UPDATE SKIP LOCKED`, so multiple replicas never double-claim. Delivery is **at-least-once** (publish-then-commit); consumers dedupe on `submission_id`. The Saga's `VerdictPublisher` port is wired to the outbox store in Kafka mode — Saga code unchanged. | No extra deployable; replica-safe by construction; durability-first per D-013. |
| **D-022** | `verdict_audit.org_id` is a **free-form tenant string with no FK** (tenancy/UUID enforcement lives at the gold-index/resolver boundary). **Pre-1.0 migration policy:** `0001_init` evolves in place and dev DBs are recreated (`docker compose down -v` + `task migrate`); append-only migrations start at the first release. | The audit log must never drop a verdict because an org row isn't provisioned; clean migration history pre-release. |
| **D-023** | The semantic service's contract is **HTTP + JSON (FastAPI/pydantic v2, OpenAPI)**, not gRPC: `POST /v1/semantic/evaluate`. Health is served on the same HTTP port (`/livez`, `/readyz`) — the `:81xx` separate-health-port convention applies to Go/gRPC services only. Local dev runs Python 3.11 (the installed interpreter); containers/CI target 3.12+. | Payloads are large text blobs (masked diff + gold context) — JSON-native; avoids Python gRPC codegen friction under `mypy --strict`; orchestrator calls it with a plain HTTP client + deadline. |
| **D-024** | **Stage-chain artifact flow + advisory stages.** `AnalysisStage` returns a `StageResult{Findings, MaskedDiff}`; a non-empty `MaskedDiff` rewrites the diff every LATER stage sees — so once the analyzer redacts secrets, no LLM tier ever receives raw values. The **cache key still derives from the ORIGINAL diff** (resubmissions must hit). Advisory stages (semantic) are wrapped in the `app.Optional` decorator: their failure becomes a `stage-unavailable` warning finding instead of triggering the fallback (which would erase required-stage findings). The semantic stage adapter composes the resolver client itself (RAG is best-effort: non-UUID org or resolver error ⇒ no context, stage still runs). | Privacy guarantee enforced structurally; graceful degradation per tier; orchestrator remains the only component talking to DB-backed services. |
| **D-028** | **Tier-2 vLLM adapter speaks the OpenAI chat-completions contract** (`/v1/chat/completions`, temperature 0) with a strict-JSON instruction; parsing tolerates fences/prose, coerces invalid severities to warning (surfaced, never dropped) and clamps `risk_score` to [0,1]; unusable responses raise. The composition root wraps it in **`FallbackLocalModel`** so a vLLM outage degrades to the deterministic heuristic — the advisory tier never dies. Config: `MEMBRANE_SEMANTIC_VLLM_URL` (empty = heuristic only). The reporter now also posts **PR comments** (markdown, fenced findings) alongside commit statuses when `pr_number` is present — same token, idempotent per notifier. | OpenAI-compat = drop-in for vLLM/DeepSeek/CodeLlama; graceful degradation per tier (mirrors D-024). |
| **D-027** | **`pkg/scan` is the single source of truth for deterministic detectors** (secrets + risky patterns + masking): the analyzer service, the orchestrator's fallback stage and the Code Sweeper CLI all delegate to it — patterns are defined exactly once. The **CLI (`clients/cli`, binary `membrane`) uses stdlib `flag` with a two-pass parse** (flags valid before/after the path), no third-party CLI framework; exit codes are a stable CI contract (0 clean / 1 findings per `--fail-on` / 2 usage). | Three duplicated regex sets collapsed into one; the CLI stays a dependency-free static binary (D-010). |
| **D-026** | **The push token deliberately has NO `workflow` scope** (user decision). Therefore `.github/` is **gitignored and never committed**; the CI definition's tracked source of truth is **`deploy/ci/github-ci.yml`**. Enabling/updating CI on GitHub is a manual one-time web-UI step (Add file → `.github/workflows/ci.yml`, paste the tracked file). Unpublished local history was rewritten once (backup branch `backup-pre-filter`) to remove the workflow file and unblock pushes — published history was never touched. | Pushes work with the user's preferred token scope; CI config stays version-controlled and reviewable. |
| **D-029** | **Container build = ONE parameterized Dockerfile for all Go services** (`deploy/docker/Dockerfile.go`, `--build-arg SERVICE=services/<svc>`, context = repo root for the `replace` directives): multi-stage on `golang:1.25` with shared BuildKit cache mounts → static binary on `distroless/static:nonroot` (no shell, no libc). Semantic = two-stage `python:3.12-slim` wheel build, runtime installs offline from wheels, dedicated non-root user. `task build:images` tags `membrane/<svc>:dev`; **`deploy/compose/docker-compose.full.yml` is the self-contained all-container profile** (`task full-up`) — Redpanda advertises dual listeners (internal `redpanda:9092`, external `localhost:19092`), a one-shot `migrate` container applies `deploy/migrations`, and services depend on it. dev.yml stays host-run-only; the two profiles are never combined. Distroless ⇒ no in-container healthchecks; probe `/readyz` from the host. | One pattern to maintain instead of five; image = D-010's multi-arch promise; full profile makes the deployment story demoable and unblocks Helm. |
| **D-025** | **Reporter notifies via Slack-compatible webhook + structured logs + GitHub commit statuses.** The contract now carries optional `commit_sha`/`pr_number` (additive across proto/envelope/domains); the GitHub adapter posts `membrane-ai/governance` statuses (approved→success, rejected→failure, needs_review→**pending**), token via `MEMBRANE_REPORTER_GITHUB_TOKEN`, base URL overridable for GHE/tests; reports without coordinates are skipped silently. **Source coordinates are NEVER cached** — the Saga strips them before caching and re-stamps from the live submission (cross-repo cache reuse). PR-comment adapter + Redis-backed delivery log remain on the roadmap. | Commit-status is the core PR-gating surface; cache must stay submission-agnostic. |
| **D-032** | **Observability is one shared `pkg/observability` package**: `Setup` installs the W3C trace-context + baggage propagator ALWAYS, and an OTLP/gRPC trace exporter + SDK TracerProvider ONLY when `OTLP_ENDPOINT` is set (empty = no-op tracing, the prod-safe default — spans cost nothing). Services never import the otel packages directly: they call `observability.Setup`/`Stop`/`Start`/`InjectHeaders`/`ExtractContext`/`TraceID`. **Distributed tracing crosses Kafka** via W3C headers — ingestion opens the originating span and stamps headers on the submission record; the orchestrator extracts them and spans the Saga (one trace ingestion→orchestrator). Each Go service wires `Setup` in its composition root (config `MEMBRANE_<SVC>_OTLP_ENDPOINT`/`_OTLP_INSECURE`) and `Stop` on shutdown; the Helm chart + full compose expose one `otlpEndpoint`/`MEMBRANE_OTLP_ENDPOINT`. **Deferred to a follow-up**: gRPC/HTTP auto-instrumentation (otelgrpc/otelhttp), OTel metrics, Python (semantic) tracing, verdict-side propagation through the outbox, and a bundled collector. | One foundation = consistent setup; Kafka header propagation is the keystone of tracing an async event system and otel has no franz-go auto-instrumentation; gating on endpoint keeps dev/test zero-dependency; the otel surface stays inside one package (adapters/composition only). |
| **D-031** | **Tier-3 premium consensus is a dual-model adapter (`premium_consensus.py`): Claude Sonnet 4.6 over the Anthropic Messages API + Gemini over Google generateContent, called directly via httpx (no SDK), each with a strict-JSON instruction.** API keys come from the **environment** (`MEMBRANE_SEMANTIC_ANTHROPIC_API_KEY` / `_GEMINI_API_KEY`), surfaced through the Helm credentials Secret — chosen over a file/vault for consistency with the service's 12-factor config (a vault backend can swap in later). Reviewers run **concurrently**; a single provider outage degrades to the survivor's findings (surfaced as an `info` finding), and only an **all-providers** failure raises `PremiumConsensusError` (→ HTTP 503 → orchestrator `app.Optional` warning, mirroring D-024). Findings are the union, tagged `premium:<model>:<rule>`. The tier runs ONLY when the gate escalates AND `PREMIUM_ENABLED=1`; enabled-but-keyless keeps `DisabledPremiumConsensus` so misconfig fails loud. The already-masked diff is what's sent — no raw secrets reach the external APIs (D-024 privacy invariant holds end-to-end). | Two independent frontier models catch more than one; native APIs avoid lossy OpenAI-compat shims; env keys match the deploy story; resilient-by-default so one vendor blip never blocks a verdict. |
| **D-030** | **Helm chart (`deploy/helm/membrane`) deploys ONLY the six platform services; Kafka/Redis/Postgres are external endpoints set via values** (matches D-011 postures — managed services in SaaS/VPC, customer-provided in air-gapped). One generic Deployment/Service template loops over `.Values.services`; env strings render through `tpl` (cross-service DNS via `membrane.fullname`); all credentials live in one optional Secret with `optional: true` secretKeyRefs (a missing credential disables that feature at the service's own boundary). Pods run non-root with the image's real UID (Go distroless 65532, semantic 10001), read-only rootfs, no capabilities. Topic provisioning is an opt-in pre-install/pre-upgrade hook Job; **no in-chart migration job** pre-1.0 (D-022 — schema is a pipeline concern, see NOTES.txt). Validate with `task helm:lint` (helm lint + template + kubeconform). | No infra-operator lock-in; one template = six services stay consistent; secure-by-default pods; chart installs cleanly with zero credentials. |
